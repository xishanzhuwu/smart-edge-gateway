# 函数指针与回调

## 1. 核心结论
函数指针是保存函数地址的指针变量。通过函数指针可以在运行时决定调用哪个函数，回调函数就是把函数指针作为参数传入，实现"公共流程+可替换行为"的解耦模式。

## 2. 为什么需要
- 中断服务函数注册：硬件触发中断时调用你指定的函数
- 状态机/事件驱动：不同状态下执行不同处理函数
- 库函数通用化：qsort的比较函数、定时器回调等
- 把公共流程与具体行为分离，减少代码重复和耦合

## 3. 语法与底层原理
声明格式：`返回类型 (*指针名)(参数类型列表);`

```c
void (*fp)(void);   // fp是函数指针，指向无参无返回值的函数
void *fp(void);     // 这是函数声明，返回void*，不是函数指针！
```

括号是关键：`(*fp)` 让fp先与*结合成为指针，再与后面的()结合表示指向函数。

函数名在表达式中会隐式转换为函数指针，因此 `fp = led_on;` 和 `fp = &led_on;` 等价。

## 4. 最小代码示例
```c
#include <stdio.h>

void led_on(void)  { printf("LED 亮\n"); }
void led_off(void) { printf("LED 灭\n"); }

// 回调函数：参数是函数指针
void set_led_state(void (*callback)(void)) {
    printf("准备设置LED...\n");
    callback();  // 调用传入的函数
}

int main() {
    void (*fp)(void) = led_on;
    fp();          // 输出"LED 亮"

    fp = led_off;
    fp();          // 输出"LED 灭"

    set_led_state(led_on);   // 回调方式
    set_led_state(led_off);

    return 0;
}
```

## 5. 嵌入式应用
- 中断回调：`void EXTI0_IRQHandler(void)` 由硬件向量表调用
- FreeRTOS任务函数：`void TaskFunction(void *pvParameters)`
- 驱动注册：把操作函数注册到驱动框架

## 6. 常见错误
- 声明时漏括号：`void *fp(void)` 变成了返回void*的函数声明
- 调用时漏括号：`fp;` 只是取地址，不会调用函数，必须 `fp();`
- 函数签名不匹配：返回值或参数类型不一致
